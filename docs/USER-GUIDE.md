# InSAR-Agent 用户手册

写给地质研究者。不需要编程背景。
InSAR 是「合成孔径雷达干涉测量」:用两次卫星雷达影像的相位差,测出地表毫米到厘米级的形变。本软件把 InSAR 数据处理交给一位「会记账的研究助理」:你说研究目标,它排好工序、跑完、留下可查证的记录。

## 第一章 五分钟上手

### 1.1 装好

在 PowerShell 里进入软件目录,执行三行命令:

```powershell
python -m venv .venv
.venv\Scripts\pip install -e .
.venv\Scripts\python -m insar_agent.api.app
```

第一行建一个独立的 Python 环境,第二行安装,第三行启动服务。窗口保持开着,它就是软件本体。以后每次使用只需要第三行。

<!-- 截图:PowerShell 启动成功,显示服务地址 -->

### 1.2 打开

浏览器访问 `http://127.0.0.1:8873`。界面分三块:左侧是会话列表,中间是聊天区,右侧是流水线面板。第一次打开会自动播放五步引导,跟着看一遍即可;想重看,点左下角导航条的「?」按钮。

<!-- 截图:工作区首页整体布局 -->

### 1.3 配模型密钥

点顶栏右上角的「模型」按钮,打开「模型接入设置」:填接入地址和 API 密钥,点「获取模型列表」,分别选一个对话模型和识图模型,点「测试对话」验证,最后「保存」。密钥只保存在你自己电脑上,不上传。这一步可以跳过,软件照样能用(见 [5.3](#53-没配模型会怎样))。

<!-- 截图:模型接入设置弹窗 -->

### 1.4 说出研究任务

在底部输入框,像给同事布置任务一样描述:研究区、时间段、想要什么分析。例如「Ridgecrest 2019 同震形变时序分析」。按回车发送。不用记任何命令。

<!-- 截图:输入框与示例任务 -->

### 1.5 看计划

Agent 会先探测你的电脑环境,然后回一张「执行计划」卡:一共几步、哪些云端已完成、每步用什么方法。点击卡片里的任意一行,可跳到右侧流水线查看该步的参数。对计划有疑问,直接在聊天里问。

<!-- 截图:执行计划卡 -->

### 1.6 确认执行

计划不会自动开始。聊天里会出现确认卡,列明将执行的步骤、预计时长、会覆盖什么。点「确认执行」才动手;也可以选「改用其它方法」或「取消」(可附理由)。执行中随时可暂停、取消,已完成的步骤不会作废。

<!-- 截图:执行确认卡 -->

### 1.7 看图与证据

跑完后,右侧面板切「影像」看形变图与时序曲线;切「审计」看每个数字的来历——方法、参数、证据级别。要写进论文,在审计页下半区点「复制引用块」,得到一段可直接贴进方法章节的文字。

<!-- 截图:影像面板与审计面板 -->

## 第二章 核心概念

### 2.1 聊天是意图,流水线是实验记录本

想象你有一位能干的研究助理。你对它说「帮我分析 Ridgecrest 2019 地震的地表形变」——这就是聊天框的用途:说研究目标、问进度、要解释。而 InSAR 处理本身是一串固定工序——找数据、配准、干涉、解缠、算时序……共 11 步,像洗照片的冲印流程。右侧流水线面板就是把这 11 步摊开:每步做没做完、用什么方法、参数是多少、出了什么文件,都可查、可改。

### 2.2 为什么不能只用聊天

因为科学计算讲究精确和留底。「滤波强一点」写不进论文,「滤波强度 0.5 → 0.6」才写得进去。一步计算可能要跑几小时,跑之前你得白纸黑字看清「将执行什么、要多久、会覆盖什么」,确认了才开始。半年后审稿人问「你当时用的什么参数」,记录本翻开就有,聊天里的口语靠不住。

### 2.3 为什么不能只用流水线

那样你就得自己学会每一步的术语和几十个参数——那是软件该干的活,不是你该干的。你说人话,它翻译成工序,并在每个决策点告诉你「为什么选这个方法」。

### 2.4 同一件事的两个窗口

聊天和面板不打架。你在聊天里说「把第 6 步换个解缠方法」,面板上第 6 步会亮起,并标出哪些后续步骤要重算;你在面板里改一个参数,聊天里自动落一张回执卡。所有正式执行都要经过聊天里的确认卡。平时多用聊天,想核对细节时再看面板。

### 2.5 证据阶梯:结果可信到什么程度

证据阶梯是系统给每次运行的「可信度评级」,共六级,从低到高:runnable(只是跑通了)→ checked → audited → calibrated → validated → publishable(达到可发表标准)。评级取所有环节中最差的一项,不虚标:有阈值未标定就升不上去,模拟演示永远停在最低级。当前级别与「为什么升不上去」在审计页实时显示。

### 2.6 provenance:处理过程的账本

provenance(溯源账本)是每次运行的完整记录:每步用的数据、方法、参数、软件版本、执行时间,以及你做过的每次人工干预。它自动生成,不需要你记笔记。审稿人要复核、师弟要复现、半年后自己要回忆,翻账本就有。查看方式见 [3.8](#38-证据账本浏览与论文引用块)。

## 第三章 功能手册

### 3.1 模型接入设置

**在哪里**:顶栏右上角「模型」按钮。
**怎么用**:填接入地址(OpenAI 兼容 /v1)和 API 密钥 → 点「获取模型列表」→ 选「对话模型」(规划、分诊用)和「识图模型」(图件识别用)→ 「测试对话」「测试识图」验证 → 「保存」。保存后新会话生效。
**注意**:密钥只保存在本机 `workspace/llm.json`,不进浏览器、不进代码库,界面永远只显示掩码。输入框留空表示沿用已保存的密钥。模型列表会显示价格与是否支持识图。

<!-- 截图:模型设置弹窗(已获取模型列表状态) -->

### 3.2 首访引导

**在哪里**:首次打开自动播放;左下角导航条「?」按钮随时重看。
**怎么用**:五步聚光灯依次介绍聊天框、流水线、干预、影像与审计、环境面板。键盘 ←/→ 前进后退,Esc 关闭。
**注意**:引导会替你切换右侧页签,结束后自动切回原页签。文案大版本更新后会自动再播一次。

### 3.3 斜杠命令

**在哪里**:聊天输入框内,以 `/` 开头即弹出候选面板。
**怎么用**:共 10 条命令——`/run`(执行)、`/pause`(暂停)、`/resume`(恢复)、`/kill`(取消,断点保留)、`/reset <步骤号>`(复位)、`/skip <步骤号>`(跳过)、`/method <步骤号> <方法id>`(改方法)、`/param <步骤号> <参数名>=<值>`(改参数)、`/status`(状态摘要)、`/help`(命令清单)。方法与参数有候选补全。
**注意**:非法步骤号、越界数值会在面板内红字提示,不会发出请求。全角数字、中文数字(如「/reset 六」)都能识别。

<!-- 截图:输入 / 后的命令候选面板 -->

### 3.4 干预回执卡

**在哪里**:聊天流右侧,你每次「动手」(改方法、改参数、执行、取消)后自动出现。
**怎么用**:卡片实时显示这次操作走到哪了:已记录 · 本地 → 提交中… → 已入队 → 已生效(执行类显示「已开跑」)。被拒绝时红字给出原因。点卡片可跳到流水线对应步骤。
**注意**:运行中的修改会标注生效时机——立即生效、本步结束后生效、或下次运行生效。这保证你清楚「我的操作到底进没进系统」。

### 3.5 计划卡与计划更新对比

**在哪里**:聊天流中。首次规划出「执行计划 · N 步」卡;计划变化时出「计划更新 · N 处变化」卡。
**怎么用**:表格列出每步的方法与变化标记——新增、移除、方法变更(旧 → 新)、参数变更(逐项列出)、需重跑。点击行可定位到右侧流水线对应步骤。
**注意**:计划没变时不会重复出卡。改动的影响范围(哪些下游步骤要重算)以卡上标记为准,不必自己推算。

### 3.6 步骤技能面板

**在哪里**:流水线面板选中某一步后,详情区的「本步技能」折叠条。
**怎么用**:展开可见这一步的领域知识,分五节:适用判据、参数启发式、常见失败与处置、QA 依据、参考文献。步骤失败时自动展开「常见失败与处置」。
**注意**:技能带版本号与内容指纹,方便引用核对(技能接口 `/api/skills` 已随
2026-08-13 版本开放);技能全文也可直接在软件目录 `skills/` 下阅读。

### 3.7 影像双图对比

**在哪里**:「影像」页签,图件网格右上角「对比」开关。
**怎么用**:打开开关,点选两张图(A、B),自动进入对比视窗。三种模式:卷帘(拖分割线看差异)、闪烁(两图交替,空格键手动切换)、并排(同步缩放平移)。滚轮缩放、拖拽平移、双击复位,可交换 A/B。
**注意**:适合对比解缠前后、不同参数产物、形变前后。Esc 退出。闪烁频率可调;系统关闭动画偏好时自动停用自动闪烁。

<!-- 截图:卷帘对比模式 -->

### 3.8 证据账本浏览与论文引用块

**在哪里**:「审计」页签下半区「完整账本 · Provenance 浏览」。
**怎么用**:头卡显示证据级、QA 结论、运行编号;「干预时间线」列出每次人工干预(全自动时明确标注「无人工干预」);「证据树」逐步展开看参数表(非默认值高亮)、指纹、等价命令行、QA 判定。操作按钮:「复制引用块」生成可贴进论文方法章节的中文文本;「导出 JSON」拿原始账本;「对比」下拉与同会话另一次运行做差异高亮。
**注意**:模拟运行的引用块会自带「不构成科学证据」警示,不要贴进论文。

<!-- 截图:账本浏览与引用块按钮 -->

### 3.9 一键体检

**在哪里**:「环境」页签底部,「一键体检」按钮。
**怎么用**:点一下,约数秒返回六大类共 21 项检查:环境(Python、依赖)、引擎(MintPy/GDAL 等)、数据库完整性、文件系统(磁盘、可写)、网络端口、WSL 状态。每项标「正常/注意/异常」,异常项附一句处置建议。
**注意**:体检只读,不修改任何东西,连点无害。任务跑不起来时,先体检再求助,多数问题的答案就在处置建议里。

<!-- 截图:体检结果分组卡片 -->

### 3.10 诊断包导出

**在哪里**:「环境」页签底部,「诊断包」卡片。
**怎么用**:点「导出诊断包」,系统把最近失败运行的日志尾部、环境探测结果、数据库摘要打成一个 zip,给出下载链接和大小。发给维护者即可,不用自己截图拼日志。
**注意**:打包内容已脱敏(去除密钥类信息),上限 50MB,超限会逐级裁剪。导出失败时按提示重试。

### 3.11 排队:消息与运行

**在哪里**:消息排队在聊天输入框上方;运行排队体现为聊天里的提示。
**怎么用**:Agent 忙碌时你照常回车,消息变成「已排队:……」小条,回合结束后自动逐条发出,点 × 可撤销。多个分析任务想连着跑,可排进运行队列:一次只跑一个,先来先跑,排队中可取消,服务重启后队列不丢,聊天里会提示「已加入运行队列:第 N 位」。
**注意**:按「停止」后消息队列保留不发。运行排队当前没有界面按钮,经接口或 MCP 使用;直接点「确认执行」仍是立即执行。

### 3.12 窄屏与分屏适配

**在哪里**:自动生效,无需设置。
**怎么用**:把窗口与其他软件分屏(如一边看文献)时,侧栏自动折叠成细条,可手动展开,偏好会被记住。窗口很窄(如半屏再半屏)时变单栏,顶部出现「会话/聊天/面板」三段导航,点着切换。
**注意**:所有功能在窄屏下都在,只是换了摆法。快捷键不变:Ctrl+B 开关右侧面板。

### 3.13 MCP 接入

**在哪里**:软件目录 `src/insar_agent/mcp/README.md` 有完整配置示例。
**怎么用**:MCP 是让 Claude Desktop、Cursor 等 AI 工具直接驱动本软件的标准接口。安装 `pip install -e ".[mcp]"`,先起本软件后端,再把 README 里的 `mcpServers` 配置粘进宿主软件。之后可在 Claude/Cursor 里说「帮我跑一个 Ridgecrest 同震分析」,由它代你建会话、规划、执行、汇报。
**注意**:走 MCP 与在界面上操作是同一套接口,账本照记。后端没启动时工具会报错并给出启动指引。

## 第四章 数据与场景

### 4.1 同震形变

**适合什么**:地震把地表错开了多少——震后快速评估、断层滑动反演的输入。同震信号量级大(数十厘米),是最容易出结果的场景。
**需要什么数据**:震前、震后各一景起步;推荐 HyP3 云端产品(配准到解缠这 2–6 步已由云端完成,本机只做时序与出图)。震后那景越早越好,晚一个重访周期就多混入一段震后滑移。
**参数关注**:形变模型选 step(阶跃),日期填发震时刻;同震属长波长信号,去斜(deramp)建议关掉,防止把形变梯度当轨道误差扣除。

### 4.2 地震时序

**适合什么**:震后地表怎么继续动——余滑、粘弹性松弛过程研究。
**需要什么数据**:震后连续覆盖的影像序列;SBAS(小基线集,一种把多景影像组网反演时序形变的方法)通常需要 10 景以上才有网络冗余,7 景是「能跑通」的下限。
**参数关注**:想试对数、指数等震后模型,用「fork 分支」对比——未受影响的步骤零重算,不要覆写原运行。注意:短观测窗内对数与指数模型几乎分不出来,报告拟合残差即可,不要断言机理。

### 4.3 冻土季节冻融

**适合什么**:多年冻土区活动层的季节冻胀/融沉,叠加长期退化沉降。信号只有毫米到厘米每年,对大气校正要求高。
**需要什么数据**:至少 2 个完整年循环(短于 14 个月时,季节项和长期趋势在数学上分不开);每个冻结季、融化季都要有影像覆盖。
**参数关注**:形变模型选 poly_periodic(年周期 + 半年周期 + 线性趋势);干涉对时间基线收紧到 24–90 天(跨冻融季的对相干性差);第 8 步 ERA5 大气校正不可省,被迫降级为经验校正时,报告里必须声明。

### 4.4 滑坡缓慢形变

**适合什么**:高山峡谷裸岩、构筑物等点状目标的蠕滑监测,量级毫米到厘米每年。
**需要什么数据**:PS(永久散射体,追踪长期稳定亮点的方法)需要 20–25 景以上的长序列;陡坡叠掩阴影严重,选轨道要结合坡向,最好升降轨互补。
**参数关注**:形变模型选 linear(蠕滑近匀速);若线性拟合残差系统性增大,那可能是临滑前兆——这是该报警的信号,别换高阶模型把它拟合掉。雷达只测视线方向(LOS)分量,换算坡向形变的投影假设必须写进报告。PS 处理链当前受工程边界限制,系统会诚实回退 SBAS 并在报告中声明。

## 第五章 排障

### 5.1 任务跑不起来:先看环境,再体检

第一步,切到「环境」页签,看引擎清单和磁盘余量——缺引擎、盘满是最常见的两个原因。第二步,点「一键体检」([3.9](#39-一键体检)):21 项检查里标「异常」的条目都带处置建议,照做即可。体检只读、秒级,放心多点。首次安装后建议先体检一轮再开始正式任务。

### 5.2 需要求助:导出诊断包

自己解决不了时,在「环境」页点「导出诊断包」([3.10](#310-诊断包导出)),把 zip 发给维护者。它包含失败日志、环境快照、数据库摘要,已脱敏。比截图有用得多:维护者能直接看到失败现场。

### 5.3 没配模型会怎样

不配 API 密钥,软件不是不能用,而是「智能层」关闭:任务识别改走内置规则(计划卡会标注「来源:rules」),常见说法(如「Ridgecrest 同震」「玉树冻土」)都能识别;流水线、干预、账本、图件全部照常。损失的是:自由问答、图件识别、措辞更自然的汇报。规则认不出你的任务时,直接在流水线面板手动选方法、点执行,效果等价。

### 5.4 常见失败速查

失败先看聊天里的分诊提示;最常见八种:

| 症状 | 原因 | 处置 |
|---|---|---|
| 数据检索 0 景 | 日期格式或平台名错 | 核对参数;去 ASF Vertex 复核 |
| 下载中途断掉 | 网络限速触发超时 | 直接重跑,断点续传 |
| HyP3 提交被拒 | 凭据缺失或配额用完 | 补凭据;或改本地路线 |
| 磁盘预检拒绝 | 景数 × 2.4 GB 超盘 | 减景数或清旧产物 |
| MintPy 硬崩(Windows) | MKL 数学库缺陷 | 切 OpenBLAS(体检会查) |
| 时序图成片空白 | 干涉网络断连 | 补干涉对或放宽时间基线 |
| ERA5 下载失败 | CDS 凭据缺且无缓存 | 补凭据;或降级并声明 |
| 全场速度整体偏移 | 参考点落在形变区 | 重选参考点,重跑 7 及下游 |

每步完整失败表见 `skills/` 目录,含文献依据。
